# v2 赛方问询清单（P3 真机对照）

只记"文档没写死、我们按假设实现"的问题。每条写明：我方假设、假设错了会牵动什么、真机上怎么对照。

---

## Q1 样本行 task 与上下文 task 不一致时，SDK 是否拒绝该行？

- **我方假设**：SDK 会把行 task 与上下文绑死，凡能到我们手里的行两者恒等；不一致的行根本不会喂进来。
- **牵动**：P0 的形状归属按 **上下文 > 行 > 产物** 实现，所以即使假设不成立（平台把不一致行也喂进来），我们仍按上下文出形状，不会出错；但"行 vs 产物分歧只出现在兜底行读不出 task 那一刻"这个论断要改写，且需要在 predict 侧补一条"行 task 与上下文冲突"的显式分支。
- **真机对照**：构造一行 `{"task":"regression","inputs":<分类形状>}`，同时给 `CONTEST_TASK=classification`，观察平台是拒该行、整批失败、还是照常喂入。看 stderr 里这一行有没有进来。

## Q2 上下文 task 与产物 task 冲突时，平台会不会真的把这一对配到一起？

- **我方假设**：不会。因此这种冲突我们按"批级配置错误"在写第一行之前 fail-fast（退出码 2，一行不写）。
- **牵动**：如果平台会配错（例如按 task 起进程但挂错产物），fail-fast 会让整批作废；那就得改成"以上下文为准、产物服务不了就走声明默认"。这属于兜底策略的边界变化，不是一行代码的事。
- **真机对照**：让 `CONTEST_TASK` 与 `CONTEST_ARTIFACT_PATH` 指向的检查点 task 故意不一致，看平台是否允许这种组合起进程。

## Q3 上下文缺失是常态还是异常？

- **我方假设**：真机上上下文常态存在（`CONTEST_PREDICTION_CONTEXT` / `CONTEST_TASK`），缺失只会出现在本地或异常环境。
- **牵动**：若真机常态缺上下文，产物 task 就从"最后退路"变成主路径，"上下文 > 行 > 产物"的优先级仍然安全，但 stderr 会逐行标注，需要在验收里把这类日志当正常而非告警。
- **真机对照**：看一次完整 predict 的 stderr，统计"上下文与行内 task 都缺失"出现次数；非零即说明假设不成立。

## Q4 父产物只暴露 `path()` 与 `checkpoint_sha256` 吗？

- **我方假设**：`rnd.parent.path(rel)` 自己会校验摘要（不符抛 `PARENT_DIGEST_MISMATCH`），`checkpoint_paths` 给出相对路径，`checkpoint_sha256` 给出声明值；我们在拿到文件后再自己算一遍 sha256 对账。
- **牵动**：若 `checkpoint_paths` 不存在，我们退到约定的 `checkpoint.npz`；若 `checkpoint_sha256` 缺省，只记录实际值并在 stderr 标注（不阻断）。若父产物有多个检查点文件，当前只取第一个，多文件场景要改候选打包。
- **真机对照**：打印 `parent` 的属性集合与 `checkpoint_paths` 长度；故意改一个字节看 `path()` 是否真的抛摘要错误。

## Q5 `state_workspace()` 的复制语义与 `save_state()` 的入参

- **我方假设**：`rnd.state_workspace(rel)` 返回一个已把 `/state` 内容复制好的可写目录（`/state` 本身只读），`rnd.save_state(path)` 接收该目录路径并整目录持久化；多次保存都以轮次开始时的状态为父。
- **牵动**：若 `state_workspace()` 只给空目录、不复制旧状态，`previous_selected_artifact_id` 会一直是 `None`，回滚链断掉；若 `save_state()` 要的是文件而不是目录，本轮保存会失败。
- **真机对照**：轮 2 启动时打印 `state_workspace()` 返回目录的文件列表，确认里面有轮 1 写的 `round_state.json`。

## Q6 `submit_candidate()` 回执里到底有哪些数字？

- **我方假设**：回执是 dict，含 `artifact_id`，并带一个验证摘要（`validation` / `metrics` / `scores` 之类）含数值，供 `reason` 引用。
- **牵动**：`reason` 只允许引平台数字，若回执没有数值，只能写"平台未返回数值摘要"——账本仍合法，但答辩时"用平台数字支撑选择"这条证据链会变弱。
- **真机对照**：原样打印一次 `submit_candidate()` 的返回 JSON（脱敏后存档），确认键名与数值位置。

## Q7 `rnd.history()` 的记录形状与 `finish(history_ids=...)` 的取值

- **我方假设**：history 是 dict 列表，至少含 `id`；我们只挑 `id / round_index / hypothesis / change_summary / artifact_id` 进提案上下文与 `history_digest`。
- **牵动**：若记录没有 `id`，`history_ids` 为空，`finish` 可能拒绝；若记录是对象而非 dict，摘要会退化成 `str(item)`，可复现性仍在但信息量下降。
- **真机对照**：轮 2 打印 `rnd.history()` 的原始结构与键集合。

## Q8 `rnd.model()` 的调用预算与空回复形态

- **我方假设**：每轮允许且只允许一次 `rnd.model()`；`max_tokens` 必须显式传，且不能超过 `rnd.max_output_tokens`（我们取 `min(512, max_output_tokens)`）；空回复表现为空字符串或 `None`。
- **牵动**：若允许/要求多次调用，提案阶段可以加一次"自检"调用；若 `max_tokens` 超限直接报错而不是截断，`min()` 的保护仍然成立；若空回复是别的形态（如空白 markdown 围栏），`_parse_proposal` 会判 `unusable`，同样退回续训父检查点。
- **真机对照**：故意传 `max_tokens = max_output_tokens + 1` 看是否报错；记录一次空回复的原始 `receipt` 形状。
