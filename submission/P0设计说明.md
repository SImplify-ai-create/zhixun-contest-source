# P0 设计说明

本轮（v2 P0）只交两件：`describe` 与 `predict`。`train` 留接口不实现。本文件记录三处容易被答辩追问的设计判断。

---

## 一、"声明默认"不是"猜"——界线在哪

这是最容易被抓的一处：`predict` 里那个 fallback 到底算不算猜。

### 先把两种行为分开

| | 猜（禁止） | 声明默认（本实现采用） |
|---|---|---|
| 前提 | 不承认自己不知道 | 承认自己不知道 |
| 做法 | 把未知伪装成已知：用残缺特征照常前向、按最近邻归类、套一个默认字段值蒙混过去，输出看起来像一次正常推断 | 给一个**运行前就已注册、与输入无关**的确定值，并明确标记这次没用上模型 |
| 可核对性 | 结果混在正常输出里，无法区分 | 触发原因逐行写 stderr，兜底值来自产物里的 `prior_*` 字段，可离线复核 |
| 出错方向 | 错得安静，且污染对模型的评估 | 错得公开，评估时能把兜底行单独摘出来 |

一句话：**猜是把未知伪装成已知，声明默认是承认未知、给最小兜底。** 两者的区别不在"输出的值像不像"，而在"有没有声明这件事发生过、值是不是事前定的"。

### 为什么必须兜底、不能报错停

平台按行喂、按行收，**缺一行就整批作废**。所以"这一行我处理不了 → 报错退出"的代价不是丢掉一行，是废掉整批。这不是严谨，是自杀。反过来，兜底也不能是"随便给个能过校验的值"——那才是猜。因此采用第三种：**总输出 + 声明默认**。

- 每一行必须吐一行，形状必须对。
- 处理不了的行，回预注册的确定性兜底。
- 触发原因写 stderr，`predict` 的退出码仍是 0（批次完整送达）。
- 兜底行在 stderr 里带行号，可以事后逐行对账。

### 兜底值是什么、从哪来

| task | 兜底输出 | 来源 |
|---|---|---|
| classification | 全 label 列表，先验多数类 `score=1.0`，其余 `0.0` | 检查点 `prior_majority_class`；未注册时退 `classes[0]` 并在 stderr 标注 |
| regression | `{"value": prior_mean}`，并 clip 到 ≥0 | 检查点 `prior_mean`；未注册时退 `0.0` 并在 stderr 标注 |

三点保证它"确定"：值不依赖输入、不依赖时间、不依赖随机数；同一行重复跑结果逐字节相同（测试 `test_declared_default_is_deterministic` 覆盖）；来源是产物文件而不是运行时推断。

分类兜底输出**完整 label 列表**而不是只给一个 label，是为了让兜底行和正常行的形状完全一致——平台侧不需要为兜底行准备第二套解析逻辑。

### 形状归属：上下文 > 行 > 产物

输出形状（分类列表还是回归 `{"value"}`）由哪一方决定，顺序是 **上下文 > 行 > 产物**：

| 情形 | 用谁 | 说明 |
|---|---|---|
| 上下文有 task（真机常态） | 上下文 | 行 task 由 SDK 与上下文绑死，两者恒等，不存在分歧 |
| 上下文缺、行 task 在 | 行 | 平台生成的行 task 仍比我们自己挂的产物可信 |
| 两者都缺 | 产物 | 最后退路，逐行在 stderr 标注 |
| 上下文与产物冲突 | —— | 批级 fail-fast（退出码 2，一行不写） |

为什么不是"产物说了算"：行和上下文由平台生成，产物是我们自己挂上去的，链条最下游的东西不该当权威。
只有当上游什么都没告诉我们时，产物才作为最后的已知信息出场。

"行 vs 产物"的分歧只可能出现在**兜底行读不出 task** 那一刻：上下文不在、行 task 也缺，
此时上下文是唯一权威但不存在，才轮到产物。一旦解析出的 task 产物服务不了，这一行走声明默认，
形状仍按产物出（否则连一行合法输出都给不出），并在 stderr 写明是哪一方来源、哪个 task 不符。

### 边界：哪些走兜底，哪些仍然 fail-fast

走兜底（行级，退出码 0）：

- 这一行不是合法 JSON、不是 JSON 对象
- `inputs` 缺失或不是对象
- 缺特征、特征不是数值、特征不是有限值
- 特征维度与检查点不一致
- 行内 `task` 取值不认识
- 按 上下文 > 行 > 产物 解析出的 task 与产物 task 不符（产物服务不了这一行）
- 上下文与行内 task 都缺（此时按产物 task 处理，不算异常，只在 stderr 标注）

仍 fail-fast（批级，退出码 2，一行不写）：

- `CONTEST_ARTIFACT_PATH` 未设置或文件不存在
- 检查点读不出、缺 `task`/`coef`/`classes`、形状自相矛盾
- 上下文 task 与产物 task 冲突

分界理由：**行级问题我们还有东西可说（先验），批级问题我们连先验都没有。** 产物读不出来时，"兜底值"本身就是编的，那就不是声明默认而是猜，必须停。上下文与产物 task 冲突时同理——用 A 的产物回答 B 的批次，输出形状都是错的，兜底也救不回来。

**兜底分支不更新流式状态。** 声明默认走的是"只读检查点与样本"的短路，不碰任何逐行累积量。否则一个坏行会把它后面的行一起带偏，那就不是"一行出问题一行兜底"，而是坏行污染整批。测试 `test_fallback_does_not_disturb_later_rows` 用 `[好行, 坏行, 同一个好行]` 锁这条：第 1 行与第 3 行必须逐字节相同。

`predict` 结束时 harness 会核对"读入行数 == 写出行数"，不等则退出码 2。这是**事后自检**，不是保护措施：走到这一步整批已经因为缺行作废了，它唯一的作用是把"总输出确实被破坏"留在 stderr 便于事后对账。真正的保护是"每一行都必须吐一行"这条设计本身。

## 二、`describe` 报两个 task，候选不申报 task

- 申报 `tasks` 的是**镜像的 `describe`**，它报 `["classification", "regression"]`——本模块两条分支都实现了，就如实报两条。
- **候选在 SDK 里不申报 task**。候选是每轮每数据集一个（A 的 checkpoint 或 B 的或 C 的），天然单任务；单个产物的 task 由检查点自己的 `task` 字段声明。
- `predict` 侧按 `CONTEST_TASK` / `CONTEST_PREDICTION_CONTEXT` **泛型分派**，不依赖候选申报。
- 形状归属按 **上下文 > 行 > 产物**：上下文与行都缺失时才用产物 task，并在 stderr 标注；行 task 认识但不符时走声明默认，不整批失败。
- 因此"一个候选要报几个 task"是假问题。真问题只有一个：镜像是两任务镜像，产物是单任务产物。

## 三、导入不往 `/app` 落 pyc

`harness.py` 在最顶行、除 `import sys` 之外任何 import 之前置 `sys.dont_write_bytecode = True`。`/app` 是只读挂载，落 pyc 会直接失败；即便可写，脏文件也会改变候选目录体积。`contest_submission.py` 自身也置了同一开关，防止被别的宿主直接导入时绕过。

验收方式不是看代码，是看目录：测试 `test_no_bytecode_written_into_app_dir` 在跑 `describe` + `predict` 前后对 `app/` 做全量快照，断言文件集合逐项不变、且不存在任何 `.pyc`。（此前在另一个包目录里出现过的 `model.cpython-312.pyc` 就是这条不成立的证据。）

## 四、两条守卫（本轮只加严，不改模型）

- **分类唯一最大**：softmax 后逐个校验 `score ∈ [0,1]` 且有限；取 argmax 时若并列，按 label 字典序取第一个，其余压到严格更低的分数，最多重试 8 轮；全零退化行给胜者一个可区分的最小正分。
- **回归 clip 到 ≥0**：`max(0.0, value)`，并校验有限。
- 两条守卫在**出站前**通过 `_assert_payload()` 再断言一遍，不依赖上游调用顺序；形状、数值域、label 唯一性、最高分唯一性都在这一层兜住。

## 五、`train` 的三条要求（P2 照做，P0 不实现）

写死在 `train()` 的 docstring 里，避免 P2 重新发明：

1. 每轮必须真的调一次 `rnd.model()`，并承担**真实提案职责**——读 history + 本轮数据 → 给出本轮候选选择。不是凑数调用，调了就要用它的输出。
2. `max_tokens` 显式设置；不要把 `rnd.prompt` 重复注入（SDK 已注入）。
3. `receipt.text` 为空时，退回"续训父检查点"，并把这件事记到 stderr。

`train` 子命令当前退出码 3、stdout 为空，`describe` 只检查 `train` 属性存在、不调用它。

## 六、P0 明确不做

检测器、轮次策略、训练侧实现、P1–P4、任何真实平台运行。P0 证明的是**协议通**，不是精度——`predict` 用的线性头只用来把形状与数值域跑对。
