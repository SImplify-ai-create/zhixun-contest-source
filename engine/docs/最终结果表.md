# 最终结果表（对外口径，供论文与答辩直接取用）

> **唯一权威版本**：`zhixun-engine/docs/最终结果表.md`。`real_data/最终结果表.md`
> 是它的**逐字节镜像**（不再单独维护）；任何改动必须两份同时更新并重新比对一致。

> 数据来源：三套公开评测数据（NASA C-MAPSS、UCI 气体传感器阵列漂移、XJTU-SY 轴承全寿命）。
> 合成流仅作内部冒烟夹具（`INTERNAL FIXTURE ONLY`），**不作为任何对外结论的证据**。
> 所有数字可由文末命令一键复现；实验记录为 `runs/*.csv`（在 `zhixun-engine/` 仓库内，每行带 `task_fuse` 字段）。

## 0. 口径边界（引用时必须一起写）

1. **不主张 SOTA**，只主张"同数据、同预算下臂间相对优势"。
2. **成本未全赢**：C-MAPSS FD001/FD004 的 C 臂标签消耗 4000，为周期重训（3600）的 111%。
3. **FD003 的"周期重训劣于从不重训 27%"只对 FD003 成立**（该子集只有一种故障模式，
   周期重训在单模式上反复过拟合），不得泛化成"周期重训一定更差"。
4. 回归任务的"标签"是 RUL 真值，分类任务的是人工类别标注；两者预算不可跨数据集相加。
5. 误报率只在气体数据的阴性对照上给出；C-MAPSS 无"已知无漂移"时段，不给误报率。
6. **XJTU-SY 的批次粒度是实验协议的一部分**：本表统一 50 文件/批。粗粒度是为了满足管线
   "每批 ≥30 条样本、验收留出 ≥30 条"的闸门；把小批次（5~10 文件/批）跑出来的三臂数值与
   本表并列比较是**无效对比**（见 §3 的"协议性空转"说明）。

必读的三条：

1. **C 在 6/6 轴承上优于静态基线**（末 5 批 0.122~0.900 倍），峰值 RMSE 5/6 更低、1 例持平；
   报警率为 1.00（退化过程持续触发），这属于数据性质，不是误报。
2. **B 在 2_1 / 2_3 / 3_3 上与 A 完全相同，是"协议性空转"而非"周期重训无效"**：
   这三个流只有 8~11 批，`period=8` 最早也要到最后一批之后才触发，评估窗口内一次都没执行。
   引用时必须写成"短流上周期重训未及触发"，不得写成"周期重训无收益"。
3. **成本未全赢**：3_1、3_4 上 B 的末段精度优于 C（0.4354 vs 0.5433；0.3046 vs 0.4560），
   但 B 花 3150 / 1950 条标签，C 只花 1640 / 540 条。C 的定位是"同量级精度下省标注"，
   不是"精度全面最优"。

**与突然失效先验的偏差（如实记录，不做因果解释）**：红线要求点名 `1_5 / 2_4 / 3_2` 为突然失效型。
其中 `1_5`(52 条)、`2_4`(42 条) 因总样本不足**未纳入实验**；`3_2` 已纳入，实测 C 臂末段 0.116，
**并未出现"突然失效型末段必然不准"的预期劣化**。原因尚未验证（未做失效机理分析），
该项以"实测为准、先验未复现"记录，不作为任何优势主张。

## 5. 融合模式对照（D5，已拍板）

| 数据集 | `or`（默认） | `perf_only`（多工况推荐） | `and`（停用） |
|---|---|---|---|
| 气体（末 3 批 F1 / 标签） | 0.467 / 2301 | 0.467 / 2301 | 0.467 / 2301 |
| FD001（RMSE / 标签） | **28.174** / 4000 | 33.091 / 3160 | 41.388 / 2120 |
| FD002（RMSE / 标签） | 35.130 / 2340 | **35.130 / 1500** | 35.130 / 1500 |
| FD003（RMSE / 标签） | **24.477** / 3220 | 27.693 / 2960 | 27.280 / 1950 |
| FD004（RMSE / 标签） | **29.452** / 4000 | 32.197 / 1840 | 32.197 / 1840 |

- 气体三模式**完全等价**：输入侧在 batch2~10 全部报警（9/9），`and` 退化为性能侧。
  故气体数据不能用于区分融合模式，只能说明"输入侧单独报警在本数据上没有判别力"。
- **FD002 是 `perf_only` 的关键证据**：6 工况切换让 `or` 在精度相同的前提上多花 840 标签
  （+56%），`perf_only` 输入侧 0 报警——"分布变但精度没掉 = 工况变化，不该重训"。
- **FD003 / FD004 与 FD001 同向**：`and` 与 `perf_only` 都劣于 `or`（FD003 24.477 → 27.280 / 27.693；
  FD004 29.452 → 32.197），但更省标签（FD003 −1270 / −260，FD004 −2160 / −2160）。
  即 `and` 的漏检代价体现在精度上，不是成本上，四个子集无一胜出。
- **默认仍为 `or`**：单工况 FD001 上 28.174 vs 33.091，9 个百分点的精度高于标注节省；
  且现有全部对外数字均由 `or` 产出。`and` 四场景无一胜出，**已停用**（代码保留、不推荐）。

## 7. 修复记录（D6）

- 概念漂移档不再清空全部历史，改为按类保留 20 条**已有标签**样本作缓冲（新增标注 0）。
- 新增"验收有效性闸门"：验收集过小、类别缺失/某类过少、或小验收集上出现 `loss≈0` 时，
  判定验收不可信，**不升级**，日志记 `accept_invalid` + reason。
- 效果：气体 batch6 崩点（C 0.229，低于静态 0.268）修复为 0.268，回到静态基线水平；
  标签消耗由 **2845** 降到 2301（**−19.1%**），即"少花标注换不再崩溃"，不宣称同时提高 F1。
- **类别缓冲为必要组件**（消融 `--class-buffer 0`）：关闭后退化为静态基线（末 3 批 0.233），
  因为单批窗口重训的模型在留出集上劣于冻结静态基线，被 `static_anchor_reject` 拒绝。

> **勘误（2026-11-11）**
>
> **1）标签基准用错（原文 4000 → 应为 2845）**
> - **原文数值**：本段原写"标签消耗由 **4000** 降到 2301（**-42%**）"。
> - **错误原因**：4000 是 `config.json` 中的 `label_budget`（预算上限），不是"缓冲关闭组"的实际消耗。
>   该组实测标签消耗为 **2845**（`runs/gas_d6_ablate_buffer0.txt` 第 26 行 `C_selfevo(or)` 行：
>   445 初始 + 3 次重训），该组从未用满 4000 上限，故以 4000 作基准属把上限当消耗。
> - **正确值**：**2845 → 2301（−19.1%）**，即 (2845−2301)/2845 = 19.1%。
> - 数值本身（2301）无误，只改基准；结论"少花标注"方向不变，幅度由 42% 收窄到 19.1%。
>
> **2）batch6 的归因不成立（数字对、原因错）**
> - **原文表述**：batch6 的 C 0.229 → 0.268 "修复"，并整体归入类别缓冲的成效。
> - **错误原因**：缓冲**关闭**组的 batch6 也是 A 0.268 / C 0.268（`runs/gas_d6_ablate_buffer0.txt` 第 17 行），
>   即该点仅由"验收有效性闸门"达成，与类别缓冲无关。
> - **正确表述**：batch6 归**验收有效性闸门**；类别缓冲的实测收益体现在末 3 批聚合 0.233 → 0.467，
>   主因是 batch9（C 0.187 → 0.818）。
>
> **3）同表其他"4000"已逐条核对，均为实测消耗，不是预算上限**：§0 第 2 条、§1 的 FD001 / FD004 的 C 标签列、
> §5 的 FD001 行——这四处是 C 臂实际跑到 4000 上限，写法正确，未改动。
> 本节勘误已同步至 `zhixun-engine/docs/最终结果表.md` 与 `real_data/最终结果表.md` 两份，内容一致。

### 9.1 XJTU-SY 口径（数字出来时必须与数字一起引用）

1. **标签**：`rul_ratio = (N − 1 − i) / (N − 1)`，1.0 → 0.0，N = 该轴承的全寿命采集次数
   （官方无逐点标签，试验在最大幅值 > 10×A_h 时立即停机，最后一个 csv 即失效时刻）。
2. **「预测值已裁剪至标签值域 [0, 1]」**——三臂一致。这是对归一化有界目标的后处理，
   **不是模型的原始输出**；任何引用这批数字的表格/图注/讲稿都必须带上这句，不得省略。
   不裁剪时无界 MLP 会向下外推出远小于 0 的值（实测 RMSE 3.6，而标签本身只有 0~1），指标失去意义。
3. **三条局限（原样保留，逐条点名）**：
   - ① 标签需要知道 N 才能构造 → **只有离线回放可得，线上不可得**，不得表述为在线 RUL 预测；
   - ② 单轴承时序切分只拟合一条退化轨迹形状，**不是跨个体泛化**（LOBO 未做，也不报）；
   - ③ **1_5 / 2_4 / 3_2 属突然失效型**（寿命 52 min / 42 min / 41 h36min 但失效位置含保持架、
     内圈、滚动体），失效前无可见前兆，末 5 批 RMSE 必然难看，属数据性质，需在结果表点名而非隐藏。
     **本次实测偏差**：`1_5`、`2_4` 未纳入实验（样本不足）；`3_2` 实测末段 0.116，未复现该先验，
     详见 §3 末尾，原因未验证，不得据此宣称"已解决突然失效"。

### 11.1 ⚠ 引用边界（必须与本节数字一起写）

### 11.2 协议

- 回测样本整段不进流（C-MAPSS 每 5 台抽 1 台保留全寿命；气体从 batch1 按步长抽 30%；

#### 12.1.1 气体 batch9 的 0.818 → 0.402 回落是怎么回事

四条证据，指向同一个结论：**这是批次有利，不是模型恢复**。

1. **同一条权重**。C 臂在批 8 评估后做 incremental 重训（累计标签 1221）；批 9 与批 10 的评估之间**没有重训**
   （下一次重训发生在批 10 评估之后，累计 2301）。因此 0.818（批 9）与 0.402（批 10）是**同一模型**的得分，
   不是"重训后又崩了"。
2. **批 9 更靠近训练分布**。以该次增量的训练批（batch8）为参照，批 9 的逐样本平均最近邻距离 = 2.75，
   批 10 = 8.23，**批 10 是批 9 的 2.99 倍**。同一模型在"近分布批"上高、在"远分布批"上低，符合预期。
3. **三臂走向分裂**。批 9→10：静态臂 0.187→0.355（升），B 臂 0.630→0.443（降），C 臂 0.818→0.402（降）。
   若 0.818 是"自进化恢复"，静态臂不应同时改善；三臂反向说明主因在批 9 本身。
4. **批构成**。批 9 只有 470 行、6 类且分布最均衡（最大类 21.5%）；批 10 有 3600 行、每类恰好 600；
   而增量重训所用的批 8 极度偏类 5（48.6%）。批 9 是"小而近分布"的有利批次。

**对外口径**：0.818 是真实的逐批得分，但**不得**写成"已恢复到 0.82"。§2 的末 3 批 0.467 含这一批，
按既定口径不改（主结果不动）；读者应理解为"批 8 0.182 / 批 9 0.818 / 批 10 0.402 的均值"，
而不是"稳定在 0.47 附近"。剔除批 9 后末两批均值 0.292——这个数只用于解释，不替换任何主表数字。

#### 12.2.2 为什么 FD001 / FD004 的 C 臂吃满 4000 标签

**标签账本（来自明细日志逐笔累加）**

| 流 | 初始窗口 | 档位重训 | 批内微调 | 合计 |
|---|---|---|---|---|
| FD001 | 600 | 0（渐变模式的档位重训不再计费） | 34 × 100 | **4000（正好触顶）** |
| FD004 | 600 | 2 × 360 | 26 × 100 + 80（末次被预算截断） | **4000（触顶）** |
| FD002 | 600 | 2 × 120 | 15 × 100 | 2340 |
| FD003 | 600 | 600 + 360 + 360 | 13 × 100 | 3220 |

机制：进入渐变模式后，管线**每批**都执行 `partial_fit`，按 `quota = max(30, round(批大小 × gradual_label_ratio))`
扣费（C-MAPSS 批 200 行 → 每批 100），且这一步**不经过收益闸门**（只有档位重训才过闸门）。
FD001 有 61 个评估批、FD004 有 157 个，只要报警持续，账单就一路累加到预算上限。
去掉初始 600 后，FD001 用 34 次批内微调、FD004 用 28 次计费事件（含 2 次档位重训）就打满剩余 3400。

**B 臂为什么停在 3600**：`arm_periodic` 每次重训按「窗口 600 条」计费，且有一条硬判定
`labels + cost > label_budget` 就跳过——600 + 5×600 = 3600，下一次需 4200 > 4000 被跳过，所以永远到不了 4000。
即"B 吃不满"是预算判定造成的，不是它更省；单位批次的标注强度上 C 并不低于 B。

#### 12.2.3 为什么 C 的 CPU 还高于 B

不是"重训更多"，而是**每批常驻开销**：

1. **初始化多 5 次拟合**：`_oof_loss` 的 5 折折外基线，使 C 的 init 阶段 = 6 次拟合（约占总 CPU 的 47–50%）。
2. **逐批双路检测**：每批做 MMD²（对冻结参考）+ KS，随历史增长而变慢；C-MAPSS 上占 11–30%，轴承上占 37%。
3. **逐批验收切片 + 静态锚评估**：每批除自评外还要评估冻结静态模型（§4 阴性对照与门槛③都依赖它）。
4. **渐变期 10 次 `partial_fit`**：每个计费批执行 10 个 epoch 的增量训练（FD001 34 批 = 340 个 epoch），
   占总 CPU 的 7–32%。
5. B 只有 6 次全量拟合 + 逐批预测，没有任何检测/验收/微调。

实测比值：FD001 2.4×、FD002 1.6×、FD003 2.1×、FD004 4.0×、气体 5.8×、轴承 1.1–3.0×。
**FD004 的 4.0× 与气体的 5.8× 最大**，对应两条流批数最多 / 批最重的场景，与上述机制一致。

> 结论三句：① **成本未全赢**——FD001/FD004 的 C 臂标签是 B 的 111%，CPU 是 B 的 2.4–4.0 倍；
> ② 但 C 在 11 条流上全部优于静态基线（10.0%–100.4%），B 在 FD003 上劣于静态 27%、在 2_1/2_3/3_3 上因周期未触发而与静态完全相同；
> ③ C 的额外算力买的是"每批都在盯漂移"，不是"更频繁重训"——档位重训次数（3–6 次）并不比 B（1–6 次）多。

## 13. A3 replay 双切片：评估后判定无效（2026-11-11）

> **引用边界（必须与本节任何数字一起写）**：本节指标是**抽走严格/宽松 eval 切片之后的"数据流指标"**，
> 口径与 §1/§2/§3 的末段主指标不同。**本跑指标不得与主结果表 §1/§2/§3 混引**，
> 也不得用来替换、加总或对照任何主表数字。本节只回答一个问题：把切片回放进训练集能否防住 A3 的遗忘。
> **答案：不能。判定无效，主仓库配置不变（`retention_rollback=false` 仍然只测不启用）。**

- 实验位置：隔离副本 `_a3_replay_20261111\zhixun-engine`，**主仓库未被触碰**，本节只归档结论。
- 与 §11 的关系：同一条 A3 抗遗忘线，但机制不同——§11 测的是"在线**闸门**"（否决坏升级），
  本节测的是"**回放**"（把切片样本混回训练集）。两者均判定无效。

### 13.1 协议

在原有三臂流程上增加一个 **replay 池**：从**初始窗口 `X0`**（第一批已标注数据，即训练流本身）中按比例抽取样本，
在每次重训时与当批训练数据混在一起。剂量 = 回放样本占训练集的比例（5% / 10% / 20%，另做 50% / 100% 扫描）。
同时保留两个切片口径：**宽**（寿命前 25%）与**严**（前 6 代 / 120 条），判定取严的那条——
任一口径不达标即记"未通过"，不只报宽口径。

### 13.2 零训练可证（回放没有偷看验收集）

1. **eval 切片行哈希与训练流交集为 0**：四条流（FD001 / FD002 / 气体 / 3_1）全部通过，验收集未被训练过。
2. **回放池 ⊆ 训练流**，且取自初始窗口 `X0`，不属于任何 eval 切片。
3. **不新增标注消耗**：回放样本是初始窗口已有的标签，复用不另计费。

### 13.3 结果（抽走 eval 切片后的数据流指标）

| FD001 严/宽 | 0.086 / 0.095 | 0.099 / 0.103 | 0.088 / 0.095 | 0.095 / 0.102 |

### 13.4 附加剂量扫描：不是剂量不够，是容量/目标冲突

| 回放剂量 | FD001 严重/宽松 |
|---|---|
| 50% | 0.132 / 0.146 |
| 100% | 0.145 / 0.159 |

剂量从 0 → 5% → 10% → 20% → 50% → 100%，末态**预测均值只到 114.1，而真值 125（目标为满 RUL 判读）**。
回放到占训练集一半以上仍在 114 附近，且继续加剂量不再改善（50% 与 100% 同量级）。

**判读：这是模型容量与目标冲突，不是"回放剂量不足"，也不是"数据量不足"。**
同一个网络既要拟合持续退化的当前段，又要保持早期寿命段的满 RUL 输出，两者在参数上互相拉扯；
回放只是把冲突样本加进同一个容量受限的模型，不能消除冲突。

### 13.5 三条不能当"通过"读

1. **FD002 的单调下降不是收益**：从 0.068 降到 0.040 看似变好，但这是"抽走切片后剩下的流恰好更容易"的口径效应，
   与回放剂量无因果；而且各臂标签消耗不同（2440 / 3180 / 3640）——replay 改变模型 → 改变报警 → 改变预算，
   是**机制副作用**，不构成算力优势。
2. **气体是唯一方向明确的**：遗忘误差 0.2886 → 0.0940（**−67%**），10% 档主任务 F1 0.5029 → 0.5324。
   方向对，但**仍未达 0.95 的判读线**，不能据此主张"抗遗忘已解决"。
3. **3_1 的 5% 档"通过"不成立**：仅更换回放池的打乱种子（42 → 7），同臂从 1.198 / 1.110 变为 0.268 / 0.240。
   种子造成的方差**不小于**剂量带来的效应量，该点不能作为收益主张。

### 13.6 与前四次的根因差异（并入 S4/S7 负结果叙述）

这是策略层自改进的**第五次尝试**，但根因与前四次不同：

| # | 尝试 | 根因 |
|---|---|---|
| 1–3 | 三个候选机制 / 同流经验 `adaptive_policy` / 跨流留一学习 | **决策点样本不足**：真实流的档位决策点只有 21–32 个，严重度与增益呈"两极 + 中间空档"，中间区间的调节命不中样本 |
| 4 | A3 在线抗遗忘闸门（§11.9） | **测试前提自毁**：闸门要么把 C 拍成 A，要么必须回放切片而失去"未参与训练"的前提 |
| 5 | A3 replay 双切片（本节） | **模型容量与目标冲突**：回放剂量加到 100% 仍只能把满 RUL 判读恢复到 114.1/125，加样本不改变同一模型的容量上限 |

结论仍是一个：**A3 按要求记"未通过"**。前四次的失效是"机制找不到该动的样本"，
这一次是"机制找到了样本但模型装不下两个目标"。两种失效都不能靠调参解决，因此不进入主配置。
